① 任务状态（status）

待执行READY
已入队，等待某 Agent 认领。这部分是当前积压的「待办池」。
干活中RUNNING
已被认领且正在执行（中间态 已领走/CLAIMED 表示认领但未开工，通常极短）。
评审中REVIEW
执行完成，等待他方（GPT/豆包/副总控）或老板评审。我最多推到这一态，不会自标已完成/DONE。
卡住了BLOCKED
被阻塞，需升级给老板做决策（如涉及核心方向/付费/凭据/正式发布）。
已完成DONE
闭环交付。仅老板/总控有资格标注，Agent 不自标。
草稿DRAFT
提案态，禁止被自动轮询执行（例：TASK-DEMO-001），需先转 READY 才进入流程。

② Agent 运行状态（runtime_status）

ONLINE/POLLING
在线轮询中——有真实定时运行证据。
IDLE
已连通但当前无任务在跑（空闲待命，正常）。
OFFLINE
无真实轮询证据，不等于没干活——可能是未到轮询时刻或数据未回写，需看 last_poll_at 判断。

③ 能力阶梯（capability_status）

SPECIFIED
能力已在文档中定义，但尚无真实运行证据。
CONNECTED
能与仓库/接口连通，有基础联通证据。
TESTED
有真实定时运行/真实证据支撑（我当前所在档位）。
PILOTED
已有至少一个真实低风险任务完整闭环——升级需真实闭环，不靠「配了定时任务」就升。

④ 优先级（priority）

P0 > P1 > P2
P0=老板拍板/核心阻塞，最高优先；数字越小越紧急。轮询只认领 P0/P1 中 assigned_agent=WORKBUDDY 且可实际完成的项。

⑤ 关于状态值中英文混用

迁移中
仓库正处于「英文状态码 → 中文六态」统一迁移期，看板会同时看到 READY 与 待执行 等并存，属正常，后续会被 validate_tasks 归一化。看板以「中文释义」为准理解即可。
阻塞中心 优先级最高 · 系统先自动恢复，无法解决才升级
Agent 运行状态 回执制：OFFLINE = 无真实轮询证据，不是没干活
任务队列 以 TASK-*.json 为唯一状态源
变更播报 各窗口同步只看 LATEST.txt 指针
最近回执 试点回执 + 任务回执
防造假声明：本看板所有数字来自仓库文件解析，「未采集」处显示未接入，不用估算冒充实测；AGENT 自报不计入完成。
